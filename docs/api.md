# API Routes

| Method | Path                        | Auth  | Purpose                                                                                                                                                                                                               |
| ------ | --------------------------- | ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET    | /health                     | no    | readiness check for the app and database, including the immutable release identifier                                                                                                                                  |
| GET    | /metrics                    | no    | Prometheus-compatible HTTP, process, and release identity metrics                                                                                                                                                     |
| POST   | /client-errors              | no    | receive bounded browser runtime error reports for structured logs and metrics                                                                                                                                         |
| GET    | /meals                      | no    | list visible meals (global + own when signed in)                                                                                                                                                                      |
| POST   | /meals                      | yes   | create meal (defaults personal; `scope: global` requires admin)                                                                                                                                                       |
| PATCH  | /meals/[id]                 | yes   | update meal                                                                                                                                                                                                           |
| DELETE | /meals/[id]                 | yes   | delete meal                                                                                                                                                                                                           |
| POST   | /meals/[id]/duplicate       | yes   | copy a global meal, including ingredients, into the caller's personal library                                                                                                                                         |
| PUT    | /meals/[id]/favorite        | yes   | set/clear the caller's favourite on a meal (`{favorite: boolean}`)                                                                                                                                                    |
| POST   | /meals/import               | yes   | parse a recipe from `{url}` or `{text}` (JSON-LD, microdata, or common HTML markup) → structured fields, no insert                                                                                                    |
| POST   | /admin/recipes              | admin | validate and queue 1–300 recipes; deduplicate by content hash                                                                                                                                                         |
| PATCH  | /admin/recipes/[id]         | admin | approve or reject a pending recipe; approval creates a global meal                                                                                                                                                    |
| GET    | /plans                      | yes   | list user plans                                                                                                                                                                                                       |
| POST   | /plans                      | yes   | create the user's plan (no body); 409 if one already exists                                                                                                                                                           |
| GET    | /plans/[id]                 | yes   | get plan + week slots (`?week=` optional, defaults to plan's weekStart)                                                                                                                                               |
| PATCH  | /plans/[id]                 | yes   | update the number of people served (`{portions}`; integer 1–100)                                                                                                                                                      |
| DELETE | /plans/[id]                 | yes   | delete plan                                                                                                                                                                                                           |
| PUT    | /plans/[id]/slots           | yes   | upsert/clear one slot (`{date, mealType, mealId}`); if the slot's meal type has a repeat pattern set, applies to every date in that day's group; 400 if the meal's `allowedSlots` excludes `mealType`                 |
| PUT    | /plans/[id]/slot-repeats    | yes   | set/clear a meal type's weekly repeat pattern (`{mealType, groupBreaks}` — `groupBreaks` is 6 booleans for the gaps Mon\|Tue..Sat\|Sun, or `null` to clear)                                                           |
| POST   | /plans/[id]/autocompose     | yes   | auto-fill empty week slots (`{week?, favoritesOnly?}` — favoritesOnly restricts candidates to the caller's favourited meals; respects each meal type's repeat pattern, picking one meal per group instead of per day) |
| POST   | /plans/[id]/copy-week       | yes   | copy one week's slots to another (`{from, to}`)                                                                                                                                                                       |
| POST   | /plans/[id]/bonus           | yes   | log an off-plan item (`{date, name, calories?, proteinG?, carbsG?, fatG?}`)                                                                                                                                           |
| DELETE | /plans/[id]/bonus/[bonusId] | yes   | remove a logged off-plan item                                                                                                                                                                                         |
| POST   | /plans/[id]/recalc-day      | yes   | re-fill one date's empty slots to fit the remaining budget after that day's bonus items (`{date}`)                                                                                                                    |
| PATCH  | /profile                    | yes   | update auto-compose preferences and nutrition targets                                                                                                                                                                 |
| POST   | /auth/register              | no    | create account after terms acceptance and privacy acknowledgement (form action)                                                                                                                                       |
| POST   | /auth/login                 | no    | start session (form action)                                                                                                                                                                                           |
| POST   | /auth/logout                | yes   | end session                                                                                                                                                                                                           |
