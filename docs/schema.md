# DB Schema

Drizzle definitions live in `src/lib/database/schema`, one table per file.

| Table             | Key columns                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `users`           | id, email, passwordHash, isAdmin (global catalogue review/edit access)                                                                                                                                                                                                                                                                                                                                             |
| `userSettings`    | userId (PK, FK) — cuisinePrefs[]/dietaryRestrictions[] and calorieTarget/proteinTarget/carbsTarget/fatTarget used by auto-compose (nullable targets; NULL → global default). 1:1 with users, created on first save                                                                                                                                                                                                 |
| `sessions`        | id (PK), userId FK, expiresAt                                                                                                                                                                                                                                                                                                                                                                                      |
| `meals`           | id, userId FK (NULL = global/shared, else personal), name, calories, proteinG, carbsG, fatG, tags[], allowedSlots[] (empty = any slot), imageUrl, description, instructions, timeMinutes, difficulty, servings (default 1)                                                                                                                                                                                         |
| `ingredients`     | id, name (unique, canonical capitalized form)                                                                                                                                                                                                                                                                                                                                                                      |
| `mealIngredients` | id, mealId FK (cascade), ingredientId FK, position, qty (nullable numeric), unit (nullable, one of `UNIT_OPTIONS` in `src/lib/constants.ts`). Source of truth for a meal's ingredient list — entered directly via the edit form's name/qty/unit rows, written through `syncMealIngredients` in `src/lib/server/repositories/meals.ts`. Backs both the meal detail display and the shopping list's quantity summing |
| `recipeImports`   | id, submittedBy FK, contentHash (unique), recipe JSON, status, mealId FK, createdAt, reviewedAt; approval creates the linked global meal                                                                                                                                                                                                                                                                           |
| `plans`           | id, userId FK (unique: at most one plan per user), portions (default 1; scales shopping quantities against each recipe's servings), name/cuisinePrefs[]/dietaryRestrictions[] (legacy internal fields), weekStart                                                                                                                                                                                                  |
| `weekSlots`       | (planId, date, mealType) composite PK, mealId FK                                                                                                                                                                                                                                                                                                                                                                   |
| `slotRepeats`     | (planId, mealType) composite PK, groupBreaks[6] booleans (gaps Mon\|Tue..Sat\|Sun; true = split, false = joined) — weekly repeat pattern per meal type; no row = every day independent                                                                                                                                                                                                                             |
| `mealFavorites`   | (userId, mealId) composite PK, both FK cascade — per-user bookmark on a meal                                                                                                                                                                                                                                                                                                                                       |
| `bonusItems`      | id, planId FK, date, name, calories, proteinG, carbsG, fatG — off-plan items logged against a day (not slot-bound, so multiple can exist per day)                                                                                                                                                                                                                                                                  |
